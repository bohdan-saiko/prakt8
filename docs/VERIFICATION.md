# Перевірка студентської роботи

Актуальний стан після вилучення автоматизованих тестів за вимогою викладача. Перевірено 28 жовтня 2026 року.

## Фактично виконано

- `npm run build`: TypeScript компілюється без помилок, код завершення 0.
- Команди package.json відповідають поточній структурі; немає посилань на видалені файли тестів.
- Непотрібний конфіг компіляції тестів видалено.
- README і STUDENT_WORK.md описують запуск застосунку та ручну перевірку.
- У docs/api.http додано приклади валідації login, негативних сценаріїв і перегляду власних сесій.

HTTP-сценарії нижче є планом ручної демонстрації, а не результатами нового запуску. У межах цього оновлення виконано перевірку збірки; застосунок і запити вручну не запускалися.

## Ручна демонстрація

Запустіть PostgreSQL, застосуйте міграції та запустіть API за README. Відкрийте docs/api.http у VS Code REST Client або використайте docs/CURL.md.

| Сценарій | Очікуваний результат |
|---|---|
| Реєстрація нового користувача | 201, тільки id/email/createdAt |
| Повторна реєстрація того самого email | 409 |
| Правильний login | 200, access у JSON, refresh в HttpOnly cookie |
| Неіснуючий email або неправильний пароль | Однаковий 401, сесія не створюється |
| Неправильний формат email, відсутній пароль або зайве поле body | 400 |
| GET /api/auth/me з чинним access | 200, безпечні поля користувача |
| GET /api/auth/me без Bearer | 401 |
| GET /api/auth/sessions із чинним access | 200, лише власні сесії, без tokenHash |
| Refresh із чинною cookie | 200, нові access та cookie |
| Повтор старої cookie після refresh | 401, відкликання всієї Session |
| Нова cookie чи access тієї самої сесії після replay | 401 |
| Logout із cookie | 204, очищення cookie та відкликання сесії |
| POST без X-CSRF-Protection | 403 |

Для replay збережіть стару cookie перед refresh. Команди з cookie-файлами є у docs/CURL.md. Після відкликання або logout виконайте новий login для продовження демонстрації.

## Перевірка реалізації та БД

- LoginDto перевіряє формат email, тип і довжину пароля. AuthService.login перевіряє користувача та Argon2id hash; для відсутнього email виконується dummy verify.
- ValidationPipe відхиляє невідомі поля. AuthGuard перевіряє підпис, алгоритм, issuer, audience, exp та активність Session. Неправильні issuer/audience відхиляються навіть за правильного підпису.
- У Prisma Studio перевірте: passwordHash починається з $argon2id$, tokenHash є SHA-256 hash, старий refresh після ротації має usedAt, Session після replay або logout має revokedAt.
- Фонове очищення за замовчуванням виконується при старті та раз на годину. Воно видаляє сесії через 7 днів після expiresAt разом з історією токенів. Retention налаштовується через SESSION_RETENTION_DAYS.

Паролі, cookie, access і refresh tokens не додавайте у звіт чи скриншоти. Схеми login/refresh, пояснення row lock і відповіді на контрольні запитання — у [STUDENT_WORK.md](STUDENT_WORK.md).
